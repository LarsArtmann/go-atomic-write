## e) WHAT WE SHOULD IMPROVE

1. **Release assessment must start with `gh run list`, not `git log`.** CI red on master = release blocked regardless of changelog content. Add to the project's release checklist: gate order is CI-green → changelog → tag.
2. **Verify external action/tool compatibility before pushing a workflow change.** One `fetch` of the action README beats a failed CI cycle. (Same class as verify-before-filing: outbound claims need source-level verification.)
3. **Cross-compile belongs in the gate.** Add `GOOS=windows go build ./...` (+ darwin) locally pre-tag and as a CI matrix job. v0.5.1 exists precisely because nobody compiled Windows.
4. **The auto-commit daemon repeatedly poisons CI.** It committed: `go 1.27.1` into go.mod (broke every build under GOTOOLCHAIN=local), and package.json bumps without lockfiles (broke `--frozen-lockfile` on 09-09, 09-13, 09-15, 09-17). Manifest and lockfile are ONE logical change split across TWO files — commit them atomically or not at all. Candidate: a CI job that runs `pnpm install --frozen-lockfile` + `go mod tidy -diff` as pure guards.
5. **LSP diagnostics were stale the entire session** (kept reporting the fixed go 1.27.1 error; exhaustruct deprecation warning persisted). When diagnostics contradict a green CLI run, restart the LSP instead of ignoring the noise for an hour.
6. **golangci-lint version skew local↔CI is now pinned but silent.** v2.13.2 is pinned in ci.yml; `.golangci.yml`'s `run.go` (1.26.7) and AGENTS.md's version line must move in lockstep on every bump — the AGENTS.md drift gotcha has now fired a 4th time; consider a pre-commit/CI check that greps the three locations for equality.
7. **Node-20-deprecation annotations** on all pinned actions (checkout, setup-go, setup-node, lint-action) — harmless today (forced to Node 24), breaking someday. Track action releases.
8. **`exhaustruct` → `exhaustruct_v5`** migration is pending (deprecation warning since v2.13.0) — one-line config change plus a lint run.
